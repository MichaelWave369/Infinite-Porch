# ADR-001: Independent Rust runtime and an authenticated local control plane

Accepted for this implementation by the attached build brief, sections 4, 21,
24, 29, 43 and 45. Candidate version: 0.1.0. This is not a production release.

Use Rust and rust-libp2p for Ed25519 peer identity, QUIC, TCP/Noise/Yamux,
mDNS, Identify, Ping and bounded request-response. LAN discovery is independent
of Internet discovery. Private application records are disclosed only to
approved peers. Do not publish community records into a public DHT.

SQLite is the durable metadata/authority/replay/accounting store. Ciphertext
blobs live in a bounded content-addressed filesystem. A single transactional
authority admission reserves each job before execution. Recovery never re-runs
a job whose external result is uncertain.

The local HTTP API binds only to loopback and requires an operator bearer token,
checks Host and Origin, and serves a React/TypeScript operator dashboard. Peer
protocol messages and local operator requests enter the same execution boundary.

Canonical signing uses protocol-domain-separated, recursively sorted JSON with
integer-only numbers and explicit versioned types. Identity keys use libp2p's
established Ed25519 implementation; blobs and protected backups use established
XChaCha20-Poly1305 and Argon2id implementations. No custom cryptography.

Start with real job-level inference, a deterministic SHA-256 task, encrypted
storage and direct messaging. Deterministic inference is explicitly a CI mock;
the Ollama adapter must never fall back to it. GPU sharing means scheduling
requests to an installed model provider; it does not pool VRAM.

AutoNAT/relay/DCUtR and private DHT are evaluated separately. No relay server
may be enabled without per-peer authorization and bounded forwarding. Public
federation, physical radio, arbitrary plugins, WASM execution and sharded model
execution require separate execution engines. Unsupported modes return REFUSE.
Native packaging and real WAN traversal need platform/field qualification.

Read-only sources inspected on 2026-10-03: PhiOS README and API Key Boundary
v0.1; SuperPhiVessel README and Governance; Commonline README and P0-f Identity
+ Authority; phibot README and Acceptance. No source code copied and no hard
dependency on those repositories. The adapters exchange observations, requests
and receipts; they never import authority from a role or model recommendation.
