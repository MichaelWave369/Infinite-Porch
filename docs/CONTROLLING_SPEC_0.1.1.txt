# 4. TWO-PHYSICAL-MACHINE QUALIFICATION

Build the repository around this real acceptance target:

MACHINE A

- Windows or Linux
- Infinite Porch node
- operator identity A
- local Ollama
- at least one model when available

MACHINE B

- Windows or Linux
- Infinite Porch node
- operator identity B
- may or may not have Ollama/model

The system must support the following real flow.

## Step A

Machine A initializes.

Machine B initializes.

Both independently generate identities.

## Step B

A creates a Porch.

A generates a short-lived invitation.

B joins.

## Step C

Both machines discover and authenticate each other.

Prefer LAN discovery where available.

Pairing must not require a central cloud account.

## Step D

A or B exposes an Ollama model.

Remote node observes the model advertisement.

Critically:

**model advertisement must NOT imply authority to invoke it.**

## Step E

Operator issues a bounded grant.

Example:

- recipient peer
- model capability
- max calls
- optional token/time/resource limits
- expiration

## Step F

Remote machine submits an actual inference request.

Routing selects the physical remote node.

Actual Ollama inference occurs.

Return:

- model output
- executor peer
- request digest
- result digest
- route decision
- timing
- authorization reference
- signed execution receipt

## Step G

Revoke the grant.

Submit again.

The request MUST fail closed.

Create evidence for both success and refusal.
