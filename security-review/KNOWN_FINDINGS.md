# Known findings and evidence limits

The 0.1.1 supply-chain findings and accepted advisory decisions are retained in `docs/SUPPLY_CHAIN_REVIEW.md` and `scripts/audit_gate.py`. Re-evaluate them against the 0.1.2 exact lockfiles and native audit receipts. An offline cached RustSec snapshot is not a fresh vulnerability-database claim; CI reports the actual attempt and command output.

The field certificate is conditional on operator attestations and signed observations from both nodes. Even independent node identities can be created by one owner on one machine. IP classification alone cannot prove physical topology or Internet absence. WAN-off therefore remains a reviewed evidence phase, and no production state exists. Windows firewall enforcement on household PCs, real mDNS, residential NAT, GPU/VRAM, hardware sustained load and independent review are not inferred from hosted CI.

Packages are unsigned and macOS packages are not notarized. A native runner architecture validates only that architecture; no universal-binary, Gatekeeper or additional CPU claim follows. The live experiment must record real runtime/weights/inference and a pinned digest; mock tests never satisfy it.

Builder regressions, intermediate failures and repairs belong in release-evidence. This file is a preparation inventory, not an independent audit result or assertion that no vulnerabilities exist.
